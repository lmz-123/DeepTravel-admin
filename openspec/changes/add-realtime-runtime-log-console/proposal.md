## Why

当前内容中台只能确认数据服务是否连接，无法在故障发生时看到 DeepTravel API 的实时输出，也无法获知 Flutter 客户端中的网络、定位、音频和未捕获异常。运营者因此需要登录服务器执行命令并来回收集手机截图，定位首页加载失败等问题耗时且缺少连续上下文。

## What Changes

- 在独立管理后台增加“运行日志”入口，分别展示后端运行日志和客户端运行日志。
- 管理 API 以只读方式跟随配置白名单内的 Docker 容器日志，并通过经过管理令牌鉴权的流式接口实时输出。
- 增加客户端日志接收接口，将经过限制、脱敏的结构化日志写入共享 MySQL，并将新增记录实时推送给已授权的后台页面。
- 日志页面支持来源、级别和关键字筛选，以及暂停、继续、自动滚动、断线重连和清空当前视图。
- 对访问令牌、密码、数据库连接串、请求头等敏感内容进行服务端脱敏；限制单条大小、批次大小、保留时间和容器来源。
- 提供 Docker Compose 与环境变量配置，使管理 API 能在部署服务器上读取指定 DeepTravel API 容器日志。
- 定义 Flutter 客户端上报协议；当前客户端需要配套接入该协议后，客户端日志页才会产生真实数据。

## Capabilities

### New Capabilities

- `runtime-log-observability`: 受保护的后端容器日志流、客户端结构化日志接收与保留，以及管理后台实时查看和筛选能力。

### Modified Capabilities

无。

## Impact

- 管理前端：`app/AdminApp.tsx`、`app/globals.css`，新增日志导航、实时流状态与日志终端视图。
- 管理 API：`server/main.py`、`server/models.py` 及拆分出的日志采集模块，新增接收、查询和流式接口。
- 部署：`docker-compose.yml`、`.env.example` 与服务依赖，增加 Docker 日志读取和客户端上报配置。
- 数据：共享 MySQL 新增客户端运行日志表，并实施索引、数量/时间保留和幂等建表。
- 外部集成：DeepTravel Flutter 客户端需使用独立上报令牌调用新增接收接口；该配套改动属于主应用仓库，不会被伪装成管理仓库内已完成的能力。
- 安全：Docker socket 仅供管理 API 使用，接口不接受任意容器名或 Docker 操作；所有日志读取接口继续要求管理令牌。
