## Why

CMS 当前把同一景点的普通站点、碎片故事、出发前内容拆在多个栏目中，并用原生路线下拉框反复选择上下文；“首页听故事”和“城市故事与出发前”也维护两套相邻入口。媒体库只有平铺资源和“服务器媒体目录”文案，无法回答资源属于哪个城市/景点、当前实际存储在本地还是 OSS。

## What Changes

- 将“站点与故事”和“碎片导览”合并为单一“景点内容”栏目；每个内容节点只使用一张精简卡片，正常编辑只展示节点名称、文案、地址/定位、标签和景点级语音生成，隐藏脚本版本、概括候选、因果链、来源声明等技术字段并原样保留既有值。
- 将工具栏“选择路线”改为“选择景点”，使用可搜索、按城市分组、带封面、发布状态与内容摘要的选择面板；保留键盘导航、清晰选中态和最近上下文，不再用难浏览的长 `<select>` 列表。
- 将景点级出发前简介/音频配置嵌入景点内容工作区，不再在城市故事栏目保留独立出发前面板；保存、审核和发布仍走明确的景点/出发前生命周期。
- 将“首页听故事”和“城市故事与出发前”收敛为唯一“城市故事”栏目；首页先展示城市卡片，进入城市后仅以“标题、城市、故事内容”维护同一种城市故事。来源类型、目录项、内容类型、投放 JSON、变体和其他技术元数据不再成为运营配置项，既有 canonical 正文与音轨仍按原身份复用。
- 移除独立“路线”和“题目”导航。路线记录继续作为景点的内部数据与客户端兼容契约，只在“景点内容”中维护必要的景点信息；题目数据和兼容 API 不在本次破坏性删除。
- 客户端日志只保存短期、有限数量记录，Docker 服务日志启用大小和文件数轮转，避免日志无限占用服务器磁盘。
- 在 legacy stop 和 managed fragment 编辑器中一致展示、保存并预览自由 `experience_tags`，避免导入、结构化编辑或旧编辑器往返时丢失。
- 将媒体库改为“城市 → 景点 → 资源”层级浏览，显示资源用途、引用对象、MIME、大小/校验和（可用时）、公共/私有 Bucket 范围、对象键以及 CDN 或鉴权访问方式；未归属/跨景点共享资源进入明确分组。
- **BREAKING**：CMS、API、开发联调和测试运行环境只允许 OSS 持久化，不再提供本地媒体模式。生产与测试完整共享相同的公共/私有 OSS Bucket、对象键、媒体引用、CDN 和私有访问逻辑，不按环境复制或隔离业务资源。公共内容走 CDN，私有内容走鉴权代理或短时签名。缺少 OSS 配置、服务配置不一致或存在本地持久引用时，CMS 必须显示阻断状态。

### Non-goals

- 不由 CMS 创建数据库 DDL，也不把 `stops` 和 `story_fragments` 强制改成同一张表。
- 不改变主服务的旅程进度、定位触发、发布锁定或媒体私有访问规则。
- 不把二进制媒体写入 MySQL，不在浏览器暴露 OSS 凭证，也不允许 CMS 直接抓取任意远程 URL。
- 不把私有 OSS 对象暴露到公共 CDN，也不允许自动化测试覆盖或删除生产与测试共用的 canonical 对象；真实 OSS 集成测试产生的临时数据仅可写入专用临时前缀。
- 不在确认新统一投影稳定前立即删除旧首页故事/出发前 API；旧入口只做兼容委托，不再作为独立运营表面。

### MVP validation goals

- 运营人员最多一次选择景点即可在一个工作区完成站点/碎片、标签、旁白与出发前配置；切换景点时有未保存保护且不会串写上下文。
- 景点选择面板可按城市浏览和搜索，在大量景点下仍能快速识别封面、状态和当前选择，并通过键盘完整操作。
- 既有首页听故事出现在唯一“城市故事”栏目中，正文/音频不复制，原发布状态和版本校验可追溯。
- 城市故事首页只出现城市卡片，进入城市后表单仅有标题和故事正文；景点节点一节点一卡片且没有概括候选等冗余必填项。
- CMS 不再显示独立路线/题目栏目；日志超过保留窗口、行数或容器文件上限后会自动清理/轮转。
- 媒体库能回答每项资源属于哪个城市/景点及其用途；共享与未归属资源不会被错误塞进单一景点。
- CMS 明确显示公共/私有 OSS 范围和 CDN/鉴权交付方式；任一运行环境缺失 OSS 配置即拒绝就绪。
- 生产与测试读取完全相同的公共和私有 canonical 对象；全量公共/私有媒体迁移后，公共资源返回相同 CDN URL、私有资源使用相同鉴权访问逻辑且没有本地媒体挂载，否则发布/迁移验收明确失败。

## Capabilities

### New Capabilities

- `scenic-content-workspace`: 定义统一景点内容栏目、优雅景点选择、出发前嵌入和标签保真。
- `city-story-administration`: 定义单一城市故事运营入口及既有首页故事的无复制复用。
- `media-library-organization`: 定义城市/景点媒体层级、OSS-only 运行时、生产/测试完整共享公共和私有 canonical 对象、公共 CDN/私有鉴权交付与全量迁移阻断提示。

## Impact

- `app/AdminApp.tsx` 及样式/组件测试：导航、景点选择面板、统一工作区、城市故事与媒体库。
- FastAPI/SQLAlchemy 管理服务：聚合景点内容、故事兼容投影、媒体反向引用/归属和存储健康信息；不拥有 Alembic。
- 共享 MySQL/API：依赖主仓库同名变更提供的字段与兼容契约。
- 部署：CMS 与主 API 的生产/测试运行时必须使用完全相同的公共/私有 OSS Bucket、对象键、媒体引用、CDN 和私有访问参数，所有运行环境缺失配置时 fail closed，且不得输出凭证。
