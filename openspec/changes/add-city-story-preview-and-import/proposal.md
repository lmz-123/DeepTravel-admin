## Why

独立后台已经可以编辑城市/路线/站点、管理碎片故事和完整故事音频，并导入单条路线包；但运营人员还不能统一配置故事在首页、旅行前和现场的复用关系，也不能上传一个多城市 JSON 后先查看新增/更新/冲突再安全写入。需求二需要在现有内容图和审核链路上补齐这些运营能力，而不是维护另一套内容结构。

## What Changes

- 增加 reusable story catalog 管理界面：从现有 fragment 或 story arc 选择 canonical 内容，分别关联已审核的短版预览音轨和现场完整音轨，并配置标题/简介/封面、城市/街区/主题/点位、故事关系及建议顺序、内容类型、现实观察细节、可选现场提示和渠道投放。
- 增加五类首页模块的后台投放、排序/权重和预览；模块类型由后台返回，示例内容与标签不是客户端硬编码选项。
- 扩展旅行前编辑，配置主题故事方向、同行标签、安全/休息/无障碍/天气适应提示和可离线准备资源；不提供答题或考试字段。
- 保留现有城市、路线、点位、故事、音频、图片、WGS-84 坐标、定位触发范围、标签、来源、事实状态、审核状态和发布状态编辑，并让新目录字段走同一保存/锁定规则。
- 增加多城市 JSON 文件上传、结构校验和 dry-run 差异预览，逐记录展示新增、更新、未变、冲突、缺失媒体和字段错误；确认后一次事务写入草稿。
- 多城市导入复用现有内容 schema、stable ID、package version、媒体库和 lifecycle service；同版本重放幂等，任何失败不留下部分写入。
- 导入包可以声明期望投放和发布配置，但导入不会直接进入已发布状态，仍须校验、提交审核、批准和显式发布。

### Non-goals

- 不在独立后台创建 Alembic migration，不复制主 API 的表所有权。
- 不新增另一套故事正文或音频文件字段，不让首页短版、现场完整版与 canonical fragment/story arc 的版本谱系漂移。
- 不在 JSON 中内嵌媒体二进制，不自动下载任意远程资源，不把导入按钮变成发布按钮。
- 不实现推荐算法、偏好问卷、实时天气抓取、答题配置或强制路线顺序。
- 不移除现有单路线导入和 legacy CRUD；它们逐步委托同一归一化服务以保持兼容。

### MVP validation goals

- 运营人员可对 legacy point、managed fragment 和完整 story arc 使用同一套关系/投放控件，并看到 canonical 正文、音频版本和发布阻塞项。
- 五类首页投放和旅行前提示可预览，未知自由标签/主题不需要后台前端代码改动。
- 一个多城市 JSON 可在零写入 dry-run 中完整列出变更和字段路径；确认导入后仍全部为草稿/待审，重复导入不重复建记录。
- dry-run 或正式导入遇到冲突、缺失媒体或无效关系时返回具体城市/路线/故事路径，正式导入整体回滚。
- 导入结果可以立即回到现有城市、路线、点位和故事编辑器继续人工修改与审核。

## Capabilities

### New Capabilities

- `city-story-catalog-administration`: 定义 canonical 故事关系、内容类型、多渠道投放、首页模块和旅行前提示的手动编辑/预览/生命周期。
- `multi-city-content-import-administration`: 定义 JSON 文件上传、dry-run 差异、字段错误、幂等事务导入、媒体引用和导入后继续编辑。

## Impact

- FastAPI/SQLAlchemy mappings：消费主 API 新增的故事目录、关系、旅行提示和导入批次表，不创建管理端 DDL。
- Admin application services：统一手动保存、单路线导入和多城市导入的规范化/验证/生命周期路径。
- Admin UI：故事目录/投放编辑、旅行前信息编辑、多城市文件选择、预览和确认导入界面。
- Existing workflows：完整故事音频、碎片旁白、媒体库、来源/主张、published lock 和显式发布继续作为权威边界。
- Companion main change：公共首页、旅行前和收藏 API 及所有数据库迁移由 `DeepTravel` 主仓库交付。
