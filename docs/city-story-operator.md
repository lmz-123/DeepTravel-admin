# 城市故事与多城市导入操作说明

## 上线前置条件

管理服务不拥有数据库迁移。先在主服务执行 Alembic `20260823_0013`，再访问 `GET /api/admin/schema/city-stories`；返回 `compatible` 后才能使用城市故事和新版导入。缺表时接口会返回 503 并列出缺失表。

## 手动编辑

“城市故事与出发前”页面包含三部分：

1. 共享故事目录：选择既有完整故事或现场故事片段，并选择属于该规范正文的审核音频。目录只配置标题、简介、封面、城市、街区、主题、点位、事实来源、可观察细节和可选现场提示，不能粘贴第二份正文或音频。
2. 五模块预览：按城市查看草稿/发布投影及阻塞项。首页模块 key 固定，内容类型、主题和标签允许使用后台新增值。
3. 出发前配置：选择主题故事，填写建议故事方向、同行标签、安全/休息/无障碍/天气适应提示和离线角色。顺序只作建议，不配置答题或考试。

已发布记录需先撤回再修改。规范正文、脚本版本或轨道 hash 改变时，目录会显示过期阻塞，必须重新选择变体并审核。

### 足迹概括字段

每个故事片段可配置“足迹编辑概括”和最多 8 条“足迹总结选项”。总结选项每行使用 `稳定ID | 概括文字`，ID 在后续修订中保持稳定且不得重复，文字不超过 160 个字符。体验标签同时作为足迹主题，允许直接录入任意新主题，不维护客户端枚举。

草稿可以暂时缺少足迹概括；进入审核、批准或发布时，空白概括、空白选项、重复 ID 和超长文字会以精确字段路径阻止操作。足迹字段不配置音频、音色、供应商或播放信息。已经发布的片段仍按现有规则先撤回再修改。

## JSON 导入

新格式示例见 [`examples/multi-city-story-v1.json`](../examples/multi-city-story-v1.json)。操作顺序：

1. 在“批量导入”选择或粘贴 JSON，点击“上传并预检”；
2. 检查新增、更新、不变、冲突、无效统计和每条 JSON Pointer；预检不会写内容表；
3. 只有无阻塞时才能点击“确认写入草稿区”；令牌 15 分钟内有效，目标被其他编辑修改后必须重新预检；
4. 导入成功后回到城市、路线、碎片导览或城市故事页面继续单项修改、提交审核和发布。

导入包中的故事片段使用 `footprint_editorial_summary` 和 `footprint_summary_options`，后者为 `{ "id": "稳定ID", "text": "概括文字" }` 数组。预检与手动编辑共用同一套规范化和发布校验；旧包缺少字段时仍可作为草稿导入，但在正式发布前必须补齐。导出后再次导入会保留字段和值，重复 ID 等错误返回对应 JSON Pointer。

权限使用现有管理 Bearer Token。审计记录只保存包标识、校验和、管理员标识、目标 revision、差异摘要和结果；不保存令牌或媒体二进制。旧的单路线碎片包和传统 `/api/admin/import` 保持兼容，但新多城市包必须使用预检/确认流程。
